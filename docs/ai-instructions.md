# Instructions for your AI: make a printer file for Printers Size Lab

You are helping someone add a printer to **Printers Size Lab** (https://nadavm-eng.github.io/printers-size-lab/),
a web page that shows printers as 3D models on a shelf and compares their size, how far they stick out,
the cable space they need behind them, their open states, prices and running costs.

**Your job:** research one printer and build the most accurate 3D model of it that your tools allow,
then deliver **exactly one file**, `<id>.printer.json`. The user drops that file onto the page.

**The bar is the printers already on the page.** Open https://nadavm-eng.github.io/printers-size-lab/
and look at them from every side, in every state (for example the HP LaserJet M110w, the Brother
DCP-L2620DW and the Xerox B230; if you can't view the page, their models and builders are in the
project's repository, see 5A): each was built in Blender from real photos of that exact model,
measured to scale, and compared with the photos side by side over several rounds until nothing big
differed. **Your model must reach that level**: section 6 lists exactly what that means, and it is your
acceptance test. Use every tool you have; where a stronger method is open to you, a weaker one is not
acceptable just because it is quicker. Spend the time it takes: a model at this level is hours of work,
not minutes, and the user would rather wait for it than get a box.

Work through sections 0 to 7 in order. Sections 8 to 12 are reference: jump to them when you need them.

## 0. Before you start

You need two things from the user: **the exact printer model** and **the country where they would buy
it**. If either is missing, ask for it first and wait for the answer. Use the buyer's country for the
price, the currency and the cartridge prices.

## 1. Take stock of your tools: try them, don't assume

Find out what you can really do by **trying each one now** with a tiny real task, not by guessing from
your general description. Write down the result of each:

| Tool | How to test it |
|---|---|
| Web search | Search for the printer's model name. |
| Opening pages | Open the maker's product page from the results and read it. |
| Downloading files | Download one product image or the user manual PDF. |
| Seeing images (vision) | Open the downloaded image and describe what is in it. If you can only read its file name or alt text, you can't see images. |
| Running code | Run `print(1+1)` in Python (or JavaScript). |
| Installing packages | `pip install bpy numpy pillow trimesh` (bpy is Blender as a Python module, no window needed; see 5A). |
| Blender | `import bpy; print(bpy.app.version_string)`, or a Blender program on the machine (`blender --background --python script.py`). |
| Giving files to the user | Write a small file and offer it to the user, or save it where the user said. |
| Helpers | Sub-agents or parallel research, if your system has them. |

Tell the user in two or three lines what you have and which route (section 2) that allows. Record the
same in the file's `made_with` block (section 9).

## 2. Take the strongest route you can

| Route | You need | What you build |
|---|---|---|
| **A. Real mesh** (best) | Running code with Blender (`bpy`) or another mesh library, and giving the user a file | A real 3D mesh: true silhouette and top profile, rounded edges, panel, display, buttons, output slot, trays, feet, a back with its ports, and every moving part separate with its pivot on its hinge. Exported as a GLB inside the printer file. |
| **B. Code-generated recipe** | Running code, but no way to make a mesh | The page's shape recipe (boxes, side profiles, cylinders, insets) generated by a script from measurements, with many shapes, rendered or plotted from the photo angles and corrected. |
| **C. Hand-written recipe** (last resort) | Text only | The same recipe, written by hand from photos or, without vision, from the manual's text. |

- **Only Route A can reach the bar.** Routes B and C give a rough block model built from a few dozen
  boxes: right size and layout, but no rounded body, seams, buttons, vents or real ports. They are
  fallbacks for assistants without mesh tools, and the page tells the visitor which route was used.
- If you can run Python, try `pip install bpy` before deciding you can't do Route A. If bpy won't
  install, `trimesh` (with `manifold3d` for cut-outs) can also build and export a GLB with named parts:
  that is Route A too.
- **The strongest form of Route A is this project's own toolkit**, which made every model on the page
  and writes exactly what the page needs (5A). Use it unless you can't run Python 3.11 or newer.
- Route A's file holds a mesh of about 0.5 to 2 MB, far too long to paste into a chat. If you can run
  code but can't hand the user a file, use Route B.
- Drop to a weaker route only after a real attempt fails, and say in `made_with.notes` what failed.

## 3. Research

**Facts** (use web search; open the pages), for the exact model and its regional variant (for example
"i-SENSYS" in Europe vs "imageCLASS" in the US, a "w" or "dw" suffix):

1. **Official closed dimensions** (width × depth × height, in mm) from the maker's spec sheet or manual,
   and **what the depth includes** (tray lip, rear bump, panel). Closed means every tray and cover shut.
2. **Maximum dimensions in use** (trays open, paper stops out, lid up), if published.
3. **Weight** in kg (and whether it includes consumables).
4. Key specs: print speed, two-sided printing, connections, paper in and out (capacity and where),
   manual feed, scanner, display, cartridges or toner (codes and ISO page yields), drum, **what is in the box**.
5. **One current price in the buyer's country, in its currency**, with the shop, a link and today's date.
   If the exact variant isn't sold there, give the closest sibling with the same body and say so in `price.note`.
6. **Running cost:** for each cartridge (toner, ink, drum): code, ISO page yield, a price in the buyer's
   country with a link, and whether it is original or compatible.
7. **The back panel:** where the power inlet and the data port are, the kind of plug, and whether each
   socket is **flat with the back** or **sunk into a recess** (and how deep).
8. Optional: how well it works on Windows, and what owners say.

**Photos.** Collect real photos of the exact model (or a sibling with the same body, which you name).
What matters most: the **back**, the **front** and the **top**; then the sides, the underside, and the
printer in each open state (trays out, paper stop up, lid up). Look in: the maker's product gallery and
press images, the user manual and quick-setup guide (dimension drawings, "parts names" pages, paper
loading pictures), big shops' galleries, review sites (they often show the back and the open trays),
video thumbnails, and used-unit listings (real photos of the back). Download them (into a working folder
if you have one) and **look at each one**: note which view it is and whether it is really this model.
Keep the page URL of every photo you use.

**Two kinds of numbers, two rules:**

- **Researched facts** (dimensions, weight, specs, prices, page yields): every one needs a source URL.
  **Never invent or guess them.** If you can't find one, leave the field out and say so in `notes`.
- **The shape** (outline, details, moving parts, pivots, socket positions): your **best estimate from the
  photos and from how this kind of printer works**. Always build it, even when no photo shows a detail,
  and say in `made_with.estimated` and `notes` what is estimated. A plain box is not acceptable when
  photos exist. Every printer has at least a place where paper goes in (front tray, cassette, rear feeder)
  and where it comes out (output tray with a flap or paper stop): model both as moving parts.
- **If you cannot see images**, read the manual's text instead: its "product parts" / "parts names"
  pages and its "loading paper" section say where each part is (for example "rear paper feed", "ink tanks
  on the right side", "output tray pulls out of the front", "USB port on the back, left"). Don't guess a
  layout from other printers when the manual says otherwise.

## 4. Measure before you model

For each straight view (front, back, side, top): find the printer's edges in pixels, and scale the
photo from an official dimension (the width in a front or top photo, the depth in a side photo, the
height in either). Then measure, in cm: the side outline (where the top slopes, steps or bulges), the
panel, display and buttons, the output slot, the trays and their lips, the feet, the seams of covers
and doors, and on the back the position and size of each socket. Write the numbers down (a short table
per view) before you build, and build from them. A photo taken at an angle can't be measured
directly: use it for what exists and where, not for exact sizes. With code and vision, crop and
measure in pixels with a script rather than by eye.

## 5. Build

### 5A. Route A with the project's toolkit (best)

The toolkit is plain Python on top of Blender's `bpy`; it makes rounded profiles, boxes, cylinders,
cut-outs, plugs with bent cables, renders from any angle, side-by-side comparison sheets, and the
exact GLB and part data the page uses.

1. Get it: `git clone --depth 1 https://github.com/NadavM-Eng/printers-size-lab.git` (or download and
   unzip https://github.com/NadavM-Eng/printers-size-lab/archive/refs/heads/main.zip). Work inside it.
2. Install: `python -m venv .venv`, then with that environment's Python: `python -m pip install bpy numpy pillow`.
   pip has bpy only for the Python version Blender itself uses (Python 3.13 for bpy 5.x, 3.11 for
   bpy 4.x). If pip finds no bpy, check `python --version` and make the environment with a matching
   Python (for example `uv venv --python 3.13`).
3. **Learn from a finished printer before you start.** Read `helper-instructions/AGENT_BRIEF.md`,
   the brief our own model builders followed (its Step 2 is the build-render-compare loop; ignore its
   parts about other sessions, the helper agent, git and the 30-minute budget, which were for our
   team). Then read one finished printer end to end: `printers/HP LaserJet M110w/measurements/MEASUREMENTS.md`
   (photo index, official size, every part measured from scaled photos, model status) next to
   `build/builders/hp_laserjet_m110w.py`, which builds exactly those numbers. `brother_dcp_l2620dw.py`
   (an all-in-one with a scanner lid) and `xerox_b230.py` are two more. Your printer gets the same: a
   `printers/<id>/measurements/MEASUREMENTS.md` written before the builder, and a builder of a few
   hundred lines.
4. Write your research as `printers/<id>/specs.json`: every field of the printer file (section 8)
   except `format` and `model`, including `made_with`. The build reads the official size from
   `dims_mm.closed`, and the packer copies the rest into your file. Keep your photos in
   `printers/<id>/photos/`; `python build/photos.py add <id> <image> --name 03_back --view back --url <image url> --page <page url> --source <kind> --evidence "<why it is this model>"`
   files one with its source, and `python build/photos.py contact <id>` makes a contact sheet of all of them.
5. Read the docstrings at the top of `build/printer_kit.py` (the `Printer` class, `extrude`, `fillet`,
   `box`, `cyl`, `cut`, `plug_cable`, `text3d`, `compare_sheet`) and start your builder at
   `build/builders/<id with - replaced by _>.py` (copy `example.py` or the finished builder closest to
   your printer). **The builder's frame is Blender's, not the
   page's:** centimetres, **Z up, the front faces −Y**, x to the right seen from the front, y = 0 at
   the middle of the depth, z = 0 under the feet. The toolkit converts to the page's frame on export.
   Name moving parts `cassette`, `input_tray`, `flap`, `support`, `lid`, `adf_tray`, `front_cover`,
   `rear_cover` (or similar), each added with `pivot=` on its hinge; add the power cable and the USB or
   Ethernet cable with `self.plug_cable(...)` at the sockets seen in the back photo.
6. Build and render (each render takes a few seconds):

       python build/build_printer.py <id> --render front,back,top,left,34fl
       python build/build_printer.py <id> --render 34fl --state printing
       python build/build_printer.py <id> --render back --cables
       python build/build_printer.py <id> --view photo07:-35:18:60     # name:azimuth:elevation:lens, to match one photo

   The build prints the closed size against the official one, the size in each state, the triangle
   count and how far the cables reach behind the back. It writes `docs/models/<id>.glb` and
   `docs/data/<id>.geom.json`; renders go to `work/renders/<id>/`.
7. Compare (section 6) with a sheet of photo next to render:

       python -c "import sys; sys.path.insert(0,'build'); import printer_kit as K; K.compare_sheet([('photo_front.jpg','work/renders/<id>/closed_front.png','front'), ('photo_back.jpg','work/renders/<id>/closed_back.png','back')], 'work/compare/<id>/round1.png')"

8. Pack the finished model and your research into the one file:

       python build/export_printer_file.py <id> --out <id>.printer.json

   It checks the GLB (self-contained, at most 8 MB and 300,000 triangles) and writes the `@2` file with
   `model.glb_base64` and `model.geom`. Give that file to the user.

### 5B. Route A with your own Blender or mesh code

Build the same things (section 2, Route A) any way you like, then follow the mesh rules in section 11
and pack the file as shown there. You may still use `build/export_printer_file.py` from the toolkit
with `--glb`, `--geom` and `--research` pointing to your own files.

### 5C. Route B: generate the recipe with code

Write a script that holds your measurements (section 4) and generates the recipe of section 10: the
body as several `profile` shapes where the width changes, boxes for trays, lids and covers, cylinders
for rollers and feet, insets for slots, displays and seams. A good model has 40 to 150 shapes. Then
render the recipe from the photo angles: turn each shape into a mesh (for example with `trimesh`, or
draw the boxes and profiles with matplotlib's 3D polygons), plot it from the same direction as each
photo, and compare (section 6). Fix the script, not the output.

### 5D. Route C: write the recipe by hand

Follow section 10, from the official box to the side outline to the details and moving parts, using
your measurements or the manual's descriptions. Check every number against the frame (section 7).

## 6. Compare and fix: the quality loop

When you can render (Routes A and B) **and** see images:

1. Render the model from the same angles as your best photos: front, back, top and one three-quarter
   view, plus each open state you have a photo of.
2. Put each photo next to its render (one sheet), and look at it.
3. List every difference, biggest first: silhouette and top profile, proportions, the size and place of
   the panel, display, slots and trays, the ports on the back, seams, colours.
4. Fix the biggest ones, render again, and repeat.

Do **at least three rounds** (our printers took three to five), and keep going until every line of the
acceptance test below holds. Keep the sheets, and count the rounds in `made_with.comparison_rounds`.
Then look at your render and one of ours (for example `docs/models/hp-laserjet-m110w.glb` rendered the
same way, or the page) side by side: if a reader could tell which one an outsider made, you are not done.

**Acceptance test: what the printers on the page have (Route A must have all of it):**

- **Size:** closed width, depth and height within **0.5 cm** of the official size; each open state
  within about 3 cm of the photos or the published size in use.
- **Silhouette:** the true side profile and top slope (steps, bulges, the hood over the output, a rear
  overhang), the plan outline and the front outline, each within about **1 cm** of a scaled straight
  photo at every point; rounded edges and corners with the real radii (bevels, `fillet`), not boxes.
- **Front and top:** the control panel with its display (lit if it is a screen), buttons and LEDs at
  their measured places; the output slot or bin with real depth (cut into the body, with its floor and
  exit), paper guides; the tray fronts with their grips; cover and door seams as thin grooves; the
  logo and model name where the photos show them (`text3d`).
- **Sides and underside:** vents and grilles, hand grips, feet.
- **Back:** the real back, not a flat wall: rear doors and their outlines, the power inlet and the USB
  or Ethernet ports at their measured positions, in their recesses if they are recessed.
- **Moving parts:** every part that opens is a separate part with its pivot on its real hinge: paper
  tray or cassette, output flap or paper stop, tray extensions, the scanner lid; a paper stack shown in
  the states where it is loaded. States `printing`, `refill` (and `lid_open` for a scanner) match the
  photos of the open printer.
- **Cables:** the power cable and the USB or Ethernet cable with real plugs, bent down behind the
  printer (`plug_cable`), so the page measures the space they need.
- **Materials:** a colour and roughness per part as in the photos (our models use about 20
  materials: body, darker trays, black slots, rubber feet, glossy display, metal, LEDs).
- **Detail budget:** about 7,000 to 40,000 triangles (ours: 7.5k to 39k), a GLB under 1.5 MB.
- **Comparison:** at least three photo-versus-render rounds, the last one with nothing bigger than
  about 1 cm wrong and no missing part; the colours read the same as the photos.

Whatever no photo shows (often the underside or the inside of a tray) is modelled plainly and listed
in `made_with.estimated`.

Without rendering or without vision you can't run this loop: check the size and frame by computing
every shape's min and max (Routes B and C), say in `made_with` that you compared nothing, and list the
views you could not check under `estimated`.

## 7. The coordinate frame (read this carefully)

The page's frame, used by the recipe (in **centimetres**) and by the GLB (in **metres**). Stand in front
of the printer, looking at its front panel:

- **x = across the width.** x = 0 is the middle of the width. **+x is to your right**, −x to your left.
- **y = height.** y = 0 is the shelf the printer stands on (the bottom of its feet). +y is up.
- **z = depth.** z = 0 is the middle of the depth. **+z is the front (toward you)**, −z is the back.

Example: a printer 36 × 25 × 20 cm (w × d × h). Its body box spans x −18…18, y 0…20, z −12.5…12.5.
A control panel on the front top edge sits at z = +12.5, y near 20. The power socket on the back is at
z = −12.5. A socket that you see on the **left** in a photo **of the back** is on the printer's right,
so it has **+x**. (The toolkit's builders use Blender's frame instead, see 5A step 5.)

## 8. Reference: the file, field by field

Fields marked *optional* may be left out. Text fields are plain text (no HTML, no Markdown).
Every `source` / `url` is a full `https://` link.

| Field | What to put |
|---|---|
| `format` | Always `"printers-size-lab/printer@2"`. |
| `id` | Lowercase letters, digits and dashes, e.g. `"canon-lbp6030w"`. The file name is `<id>.printer.json`. |
| `name`, `brand` | Full model name with the brand, as sold in the buyer's country (e.g. `"Canon i-SENSYS LBP6030w"`), and the brand. |
| `type` | Short, e.g. `"Mono laser printer"`, `"Colour inkjet all-in-one"`. |
| `functions` | *optional* List from `"print"`, `"scan"`, `"copy"`, `"fax"`. |
| `buyer_country` | The user's country, e.g. `"Israel"`. |
| `dims_mm.closed` | `{"w", "d", "h", "source", "includes"}`: official closed size in **mm**; `includes` = what the depth covers. Required. |
| `dims_mm.max` | *optional* `{"w", "d", "h", "what", "source"}`: largest size in use, mm; `what` says what is open. |
| `weight_kg` | *optional* `{"value", "what", "source"}`. |
| `specs` | *optional* List of `{"label", "value", "source", "note"}`. Use these labels where they fit: `Print speed`, `Two-sided printing`, `Connections`, `Paper in`, `Paper out`, `Manual feed`, `Scanner`, `Display`, `Toner`, `Ink`, `Drum`, `In the box`. `value` is text, or a list of texts for `In the box`. Other labels are allowed. |
| `price` | *optional* `{"value", "currency", "where", "url", "date", "note"}`: one price in the buyer's country. `currency` is the 3-letter ISO code (`"ILS"`, `"EUR"`, `"USD"`…), `date` is `YYYY-MM-DD`. |
| `running_cost.cartridges` | *optional* List of `{"code", "kind", "pages", "price", "currency", "original", "where", "url"}`. `kind` is `"toner"`, `"ink"` or `"drum"`; `pages` is the ISO yield; `original` is `true` for the brand's own cartridge. Leave out starter cartridges that come in the box. For colour inkjets list the black cartridge first. |
| `running_cost.compatible` | *optional* `{"allowed", "note", "source"}`: can third-party cartridges be used? `allowed` is `"yes"`, `"nags"`, `"blocked"` or `"unknown"`. |
| `software.windows`, `software.owners` | *optional* `{"rating", "why", "source"}`, `rating` is `"good"`, `"mixed"`, `"poor"` or `"unknown"`. |
| `cable_space.sockets` | *optional* The plugs on the back, see below. Leave it out when your mesh has its own cables. |
| `cable_space.why` | *optional* One or two sentences on what sets the space needed behind the printer. |
| `notes` | What a buyer should know about its size and shape, which parts of the shape are estimated, and **what you could not find**. At most 6 short sentences, impersonal (no "I"). |
| `made_with` | How the model was made, honestly (section 9). |
| `model` | The 3D shape: a recipe (section 10) or a mesh (section 11). |

**Sockets.** Each one is `{"kind", "x_cm", "height_cm", "recess_cm", "back_z_cm"}`:
`kind` is `"C13"` (kettle-style 3-pin power), `"C7"` (2-pin "figure 8"), `"C5"` (3-pin cloverleaf),
`"DC"` (round plug from an external power brick), `"USB-B"`, `"RJ45"` (Ethernet) or `"RJ11"` (phone);
`x_cm` is the socket's x (left in a photo of the back = +x); `height_cm` its height above the shelf;
`recess_cm` how deep the socket sits inside the outline (0 = flat back; 2–4 for a socket in a pocket);
`back_z_cm` *optional*, the z of the back surface at the socket, only when that part of the back is in
front of the rear-most point (a socket under a rear overhang). The page draws the plugs and cables and
works out the space behind: a plug on a flat back needs 5–8 cm, a recessed one only 1–2 cm. List only
power and data sockets that are used. Give the sockets from any photo of the back; leave them out only
if you found no picture of the back at all (the page then assumes 8 cm).

## 9. Reference: `made_with`

Say exactly how the model was made. The page shows it to the visitor next to the model.

```json
"made_with": {
  "route": "A",
  "tools": ["bpy 5.2.3", "Printers Size Lab toolkit", "vision", "web search", "Python"],
  "photos_used": 14,
  "comparison_rounds": 4,
  "verified_from_photos": ["front", "back", "top", "left side", "printing state"],
  "estimated": ["underside", "inside of the rear tray", "lid hinge position"],
  "notes": "One short paragraph: anything a reader should know, e.g. what was tried and failed."
}
```

`route` is `"A"`, `"B"` or `"C"`. `photos_used` counts only images you actually looked at;
`comparison_rounds` counts photo-versus-render rounds (0 if you rendered nothing). `verified_from_photos`
names the views you compared with a photo; `estimated` names what no photo or drawing showed you. An
assistant that could not see images writes `"photos_used": 0`.

## 10. Reference: the shape recipe (Routes B and C)

```
"model": {
  "units": "cm",
  "parts": [ {"name": "body", "shapes": [ ... ]}, {"name": "lid", "pivot": {...}, "shapes": [ ... ]} ],
  "states": { "printing": [ ... ], "refill": [ ... ], "lid_open": [ ... ] }
}
```

**Parts.** The first part is `"body"`: everything that never moves. Every part that moves (paper tray,
cassette, output flap or paper stop, scanner lid, front door that opens to load paper) is its own part
with a `name` (lowercase, e.g. `"input_tray"`), a **`pivot`** `{"x", "y", "z"}` on its hinge line (for a
part that only slides, any point on it, e.g. its front-bottom middle) and its shapes. Add `"hidden": true`
to a part that only appears in some states (a stack of paper in an open tray). **Write every shape where
it is when the printer is closed**, in the frame of section 7, never relative to the pivot.

**Shapes.** Each shape gives a from–to range on axes. Common keys: `"color"` (`"#rrggbb"`), `"roughness"`
(0 shiny … 1 matte, default 0.55), `"glow"` (`"#rrggbb"`, only for a lit display or LED).

- **Box:** `{"type": "box", "x": [x1, x2], "y": [y1, y2], "z": [z1, z2], "radius": 0.8}`. `radius`
  *optional* rounds the edges (cm).
- **Profile** (side outline pushed across the width, for sloped tops, curved fronts, wedges):
  `{"type": "profile", "x": [x1, x2], "zy": [[z, y], [z, y], ...]}`. `zy` lists the corners of the side
  outline as **[z, y] pairs (depth first, then height)**, going around the outline once, as seen from
  the printer's right side. 3 to 64 points.
- **Cylinder:** `{"type": "cylinder", "axis": "x", "x": [x1, x2], "y": 3, "z": 10, "radius": 1}`. Along
  `axis` give a range; on the other two axes give the centre as a single number.
- **Inset** (a flat dark rectangle drawn on a surface: output slot, recess, display, button panel):
  `{"type": "inset", "face": "front", "x": [x1, x2], "y": [y1, y2], "z": 12.5, "color": "#111111"}`.
  `face` is `"front"`, `"back"`, `"top"`, `"left"` or `"right"`; the axis that faces that way gets a
  single number (the surface position) and the other two get ranges. Insets do not change the size.

**Order of work:** (1) the official box: `x` −w/2…w/2, `y` 0…h, `z` −d/2…d/2 (w, d, h from
`dims_mm.closed` in cm); everything stays inside it when closed, unless the official depth leaves
something out (say so in `notes`). (2) Replace it with the real side outline: `profile` shapes, split
where the width changes. (3) What changes the silhouette or what a viewer recognises: panel, output slot,
tray fronts, scanner lid, feet, display (inset with `glow`). (4) Moving parts with pivots, then states;
if `dims_mm.max` is published, size the moving parts so the open states reach it. (5) Real colours
(most printers are off-white `#e8e8e6`, light grey or black `#202122`), darker for trays and slots.
No logos or text. Limits: 400 shapes, 24 parts, file under 500 KB.

**States** (lists of operations on parts; define only those that apply):

- `"printing"`: what is out while printing: paper stops and output flaps flipped out, an input tray
  opened with paper in it.
- `"refill"`: loading paper: the cassette pulled out, or the input tray opened.
- `"lid_open"`: only for a scanner: the lid raised (about 70–80°).

Operations: `{"part": "lid", "rotate": {"axis": "x", "deg": -75}}` turns the part about its pivot;
`{"part": "cassette", "move": {"z": 25}}` slides it (cm); `{"part": "paper", "show": true}` /
`{"part": "paper", "hide": true}`. Rotation directions about `x` (seen from the printer's right side):

| Motion | Rotation |
|---|---|
| Lid hinged at the back, lifting up | `"axis": "x", "deg": -75` |
| Front cover or tray hinged at its **bottom** edge, falling open toward you | `"axis": "x", "deg": 90` |
| Flap lying flat on top, hinged at its **front** edge, flipping up and over toward the front | `"axis": "x", "deg"` between 70 and 160 |
| Flap lying flat on top, hinged at its **back** edge, lifting up | `"axis": "x", "deg": -70` |
| Rear input tray standing up, hinged at its bottom, leaning back | `"axis": "x", "deg": -20` |

Positive degrees about x tip the part's top toward the front; negative tip it toward the back.

## 11. Reference: the mesh (Route A)

`model` is then `{"glb_base64": "...", "geom": {...}}`. The toolkit's packer writes both (5A step 8).
If you build the GLB another way, it must follow these rules, or the page rejects it or shows it wrong:

- **One self-contained binary glTF (.glb):** everything inside the file, nothing referenced by a `uri`
  (no outside files, no web addresses). At most **8 MB** and **300,000 triangles**. No Draco or meshopt
  compression, no KTX2 textures; textures are PNG or JPEG of at most 4096 px a side (plain colours
  are usually better than textures).
- **Frame:** metres, **+Y up, the front faces +Z**, x to the right seen from the front, origin at the
  bottom centre of the closed body (section 7, in metres). Blender: File > Export > glTF 2.0, format
  glTF Binary, "+Y Up" ticked, "Apply Modifiers" ticked; in Python
  `bpy.ops.export_scene.gltf(filepath="x.glb", export_format="GLB", export_yup=True, export_apply=True)`.
  Blender's own frame is Z up; with +Y Up export, Blender's −Y becomes the page's front.
- **Closed** = the pose in the file: every tray and cover shut. It must match `dims_mm.closed` within
  0.5 cm (the page measures it and warns otherwise).
- **One node per part**, named `<id>_<part>`: `<id>_body` for everything that never moves, and each
  moving part separately. **A moving part's node origin is on its hinge** (for a sliding part, any point
  on it): the page turns and slides the node about its own origin.
- **Cables** (optional but best): each plug with its cable, bent down behind the printer as it would be
  when pushed against a wall, as its own node `<id>_cable_<name>` of kind `"cable"`. The page measures
  the cable space from them and hides them with its Cables switch. Without cable nodes, give
  `cable_space.sockets` and the page draws the plugs itself.
- **`geom`**, in the same frame (metres):

```json
"geom": {
  "parts": {
    "body":        {"node": "canon-lbp6030w_body", "kind": "body"},
    "cassette":    {"node": "canon-lbp6030w_cassette", "kind": "moving"},
    "flap":        {"node": "canon-lbp6030w_flap", "kind": "moving"},
    "paper":       {"node": "canon-lbp6030w_paper", "kind": "moving", "hidden": true},
    "cable_power": {"node": "canon-lbp6030w_cable_power", "kind": "cable"}
  },
  "states": {
    "printing": [{"part": "flap", "rot": [1, 0, 0], "deg": 80}],
    "refill":   [{"part": "cassette", "move": [0, 0, 0.22]}, {"part": "paper", "show": true}]
  }
}
```

  `kind` is `"body"`, `"moving"` or `"cable"`; `"hidden": true` hides a part until a state shows it.
  A state operation turns a part about its node origin (`"rot"`: an axis `[x, y, z]`, `"deg"`; positive
  degrees about `[1, 0, 0]` tip the part's top toward the front), slides it (`"move"`: metres), or
  shows or hides it. `build/build_printer.py` writes exactly this in `docs/data/<id>.geom.json`.
- **Packing by hand** (when you don't use `build/export_printer_file.py`), in Python:

```python
import base64, json
f = json.load(open("research.json"))          # every field of section 8 except "format" and "model"
f["format"] = "printers-size-lab/printer@2"
f["model"] = {"glb_base64": base64.b64encode(open("printer.glb", "rb").read()).decode("ascii"),
              "geom": json.load(open("geom.json"))}
json.dump(f, open(f["id"] + ".printer.json", "w"), ensure_ascii=False)
```
